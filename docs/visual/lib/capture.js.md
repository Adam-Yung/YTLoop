# visual/lib/capture.js

Real-screen evidence on macOS and Windows (`supported` is false elsewhere and every function degrades to a no-op or `false`). Runs on the test VM (decision 0008). Windows calls go through the persistent PowerShell helper in `win.js` (decision 0010); the macOS commands are unchanged.

- `screenshot(file, width = 0)`: macOS `screencapture -x -D 1`, then `sips --resampleWidth` when a width is given; Windows `Shot` (primary display, same downscale).
- `startRecording(file)` returns `{ stop() }`: macOS: `screencapture -v` video of display 1, stopped with SIGINT. Windows: `ffmpeg -f gdigrab -framerate 10 -c:v libx264 -preset ultrafast`, found at `YTLOOP_FFMPEG`, `~\tools\bin\ffmpeg.exe` or on `PATH`, stopped by writing `q` to its stdin. `stop` waits up to 8 s, kills a recorder that is still running, and returns whether a non-empty file exists.
- `startSampler(dir, everyMs)` returns `{ stop() }` that resolves to the list of sample files: a screenshot every `everyMs`, downscaled to 640 px wide (`sips` on macOS, in the screenshot itself on Windows). Replaces ffmpeg frame extraction. A missed sample is skipped; a slow screenshot never overlaps the next.
- `windowGeometry(page)`: `window.screenX/Y`, outer/inner size, `screen` size.
- `elementOnScreen(page, png, selector)`: element box in screen-PNG pixels. Scale is `png.width / screen.width`; the top browser chrome height is `outerH - innerH`. Calibrated against real screenshots on the Mac (2x); other displays differ and are re-verified by `launch.4`.
- `raiseWindow(page, cfg)`: `page.bringToFront()`, then activates the app's own browser process: finds the main process whose command line has `--user-data-dir=<cfg.profileDir>` (via `ps`) and, on macOS, calls `NSRunningApplication.activateWithOptions` through `osascript -l JavaScript`. This is needed with real Chrome: the person's own Chrome windows belong to the same app name, so `open -a "Google Chrome"` raised the wrong window and covered the app's page (4 `vm:verify` checks failed). Needs no Accessibility or Automation permission. On Windows the pid comes from `Win32_Process` and the window is raised with `SetForegroundWindow` (`win.js`).
- `isFrontmost(cfg)`: true when the frontmost application (macOS) or foreground window's process (Windows) is the app's own browser process (same pid lookup as `raiseWindow`); true on platforms without screen support.
- `readPng(file)`.
